Trae 的 --install-extension CLI 通道被阉割（静默失败），须采用旁载方式：把插件目录注册进 Trae 的扩展权威清单。
复制插件目录
将 extension/（含 extension.js 与 package.json）拷贝到 C:\Users\<用户>\.trae-cn\extensions\hackathon-lm-probe.lm-probe-0.0.1\
注册进权威清单
运行 python scripts/register_ext.py（自动备份 + 幂等注册）；或手工编辑 extensions.json，条目格式见仓库 README。清单中不能有重复 id 条目，location.path 必须是 scheme:"file" 的绝对路径（URI 风格 /c:/...），否则扩展不激活且无提示。
重载窗口
Ctrl+Shift+P → Reload Window。两个标志同时出现即部署成功：右下角通知「ContextKeeper 已启动（优化模式）」与底部状态栏右侧常驻条目 ⚡ CK 优化 | 已省 N tok
验证
在对话中输入"调用 read_file_smart 读取任意代码文件"——智能体自主调用并返回压缩骨架；或输入 /optimize 验证模式开关

🛠️ 四个 MCP 工具

工具用途关键参数
read_file_smart智能读取文件：返回结构骨架（签名 + docstring + 关键行），超长函数体省略为行号索引，节省 50~80% tokenpath（必填）；body_keep_lines：保留体首 N 行，默认 4；full：true 直接返回全文
load_context_ref无损解引用：按 REF 编号 + 行号取回省略的原文，支持多区间ref_id（必填，如 ck-5）；ranges：如 "42-87,100-120"；省略返回全文
contextkeeper_mode模式开关：优化 ↔ 常规，跨对话持久化，切换时弹通知mode：optimize / normal / status
context_stats实时 token 账单：调用次数、节省量、节省率，自动落盘无

🎮 使用方式（用户视角）

日常使用——什么都不用做

插件注册的工具对智能体透明。正常下达任务（如"分析这个文件的路由结构"），智能体读取大文件时自动优先使用压缩读取，需要细节时自动取回——用户全程无感知。

状态栏实时账单

IDE 底部状态栏常驻显示：⚡ CK 优化 | 已省 38,837 tok（模式 + 累计节省量，每次调用实时刷新，重启 IDE 自动从账单恢复累计值）。鼠标悬停看明细，点击弹出账单摘要。

模式开关

输入效果
/optimize开启优化模式（默认）：读取走结构骨架压缩，省 token
/normal切回常规模式：read_file_smart 全文返回，常规消耗

模式写入工作区 .contextkeeper/mode.json，跨对话、跨 IDE 重启持久生效。

数据留痕（可审计）

  • .contextkeeper/stats.jsonl —— 每次调用的 token 账单原始记录（部门报表数据源）
  • .contextkeeper/refs/ck-N.json —— REF 影子存储（上限 200 条 LRU），重启 IDE 后仍可取回

⚙️ 压缩引擎：三模式 + "叶子优先"选择策略

模式适用策略
花括号语言结构骨架JS / Java / C / C++ 等大括号配对建块；类/命名空间签名保全渲染（成员签名全保留、成员体整体省略）；独立大函数保留头 4 尾 3 行
Python 结构骨架.py / .pywdef/class 缩进块识别（装饰器并入签名）；类内方法签名 + docstring 全保留，方法体整体省略
generic 首尾截断>400 行非代码文本前 120 行 + 后 60 行

选择策略："叶子优先 + 包裹结构签名保全"

  • 叶子优先：候选块按嵌套深度降序选择——方法（叶子）先于类被选中，保证方法级压缩粒度
  • 包裹结构识别：顶层块若含 ≥2 个定义型直接子块（类/命名空间），改用签名保全渲染——所有成员签名保留，成员体整体省略为行号标记
  • 智能跳过：小文件或压缩收益 <10% 自动原样返回

压缩输出的每一处省略都形如：

def _clip(text: str, n: int = _STATS_SAMPLE_CHARS) -> str:
    """Truncate a sample's text to n chars, marking how much was dropped."""
    [CK-OMITTED 原文行 57-58（省略 2 行）—— 调用 load_context_ref(ref_id="ck-5", ranges="57-58") 可查看]

签名（是什么）+ docstring（做什么）+ 行号索引（细节在哪）——模型拿到的是"完整目录 + 每章摘要 + 精确页码"。

🎯 为什么减 token 且不影响模型自主分析？

核心设计：压缩不删除信息，只改变信息的呈现密度。信息链路四层保障：

① 结构完整性——模型"看得见全局"

所有类与方法签名、import、注解、docstring 全部保留（实测 server.py 2239 行压缩后 46 个方法的 docstring 全部可见）。结构分析、功能定位、调用关系梳理占日常任务 80% 以上，基于骨架即可完成。

② 信息对称——模型"知道自己没看什么"

与一刀切截断的本质区别：每处省略都有带精确行号的 [CK-OMITTED] 标记。模型明确知道哪段没读、怎么取回，从根本上杜绝"看不见就瞎编"。

③ 按需解引用——模型"要细节时自己取"

触发完全由模型自主判断，无需人工指定，三层引导：省略标记内嵌"取回说明书"（直接写明调用参数）、工具 description 注明适用场景、输出头部附分析指引（"需要被省略段的完整实现时，请主动按行号取回，不要基于签名推测"）。

实测验证：真实对话中智能体在追问方法实现时自然调用 load_context_ref 精确取回正确区间，全程无人工干预。

④ 用户兜底——始终有选择权

三种逃生通道：/normal 一键全量模式（跨对话持久）；body_keep_lines 放宽保留行数；full=true 单次读全文。REF 落盘持久化，IDE 重启后历史省略段仍可取回。

⚡ 性能特征

项表现说明
压缩耗时毫秒级2239 行文件为正则 + 行扫描一遍处理
CPU单核瞬时，无持续负载纯字符串规则，无模型推理
内存仅 REF 缓存，上限封顶200 条 LRU，单文件 MB 级
网络零请求纯本地运行，断网可用

唯一成本转移：模型多一次解引用调用（约几百 token）换取一次上万 token 的读取节省，量级上完全划算。
